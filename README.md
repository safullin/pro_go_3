# GophKeeper

GophKeeper — клиент-серверный менеджер приватных данных. Пользователь может хранить пары логин/пароль, тексты, файлы и банковские карты с произвольной метаинформацией. CLI работает на Windows, Linux и macOS, а изменения синхронизируются между клиентами через gRPC.

## Возможности

- регистрация и аутентификация пользователей;
- клиентское шифрование данных AES-256-GCM;
- вывод ключа из мастер-пароля с помощью Argon2id;
- хранение паролей пользователей в виде bcrypt-хешей;
- защищённый gRPC-транспорт с TLS 1.3;
- создание, просмотр, изменение и удаление приватных данных;
- поиск по названию и метаинформации на стороне сервера;
- синхронизация по монотонному курсору с передачей удалённых записей;
- зашифрованный локальный кеш для чтения данных без подключения к серверу;
- защита от конфликтов при одновременном изменении записи;
- PostgreSQL-хранилище с автоматической миграцией;
- корректное завершение сервера по `SIGINT`, `SIGTERM` и `SIGQUIT`.

## Архитектура

Сервер хранит учётные записи, зашифрованные блоки и метаданные синхронизации. Содержимое записи шифруется на клиенте и не передаётся серверу в открытом виде. Название и пользовательская метаинформация хранятся отдельно для серверного поиска и также входят в зашифрованный блок, чтобы клиент мог проверить их целостность. Ключ шифрования выводится из мастер-пароля и индивидуальной соли пользователя и существует только в памяти клиента.

Протокол описан в [`proto/gophkeeper.proto`](proto/gophkeeper.proto). Для обмена используется бинарный протокол gRPC. Обновления защищены optimistic locking: клиент передаёт известную версию записи, а сервер отклоняет устаревшее изменение кодом `Aborted`.

При сохранении имя ограничено 255 символами, метаинформация 4096 символами. Миграция `003_secret_metadata_limits.sql` переводит эти столбцы в `VARCHAR`. Если в существующих столбцах есть значения длиннее лимита, миграция завершится ошибкой без обрезания данных: их нужно предварительно сократить.

Записи, созданные до миграции `002`, остаются доступными: при пустом отдельном имени клиент восстанавливает имя и метаинформацию из расшифрованного содержимого. Для серверного поиска по таким записям их нужно повторно сохранить клиентом.

## Запуск

Для сервера нужны PostgreSQL, секрет подписи токенов длиной не менее 32 символов и сертификат TLS. Для локальной разработки можно создать самоподписанный сертификат:

```bash
mkdir -p certs
openssl req -x509 -newkey rsa:4096 -sha256 -days 365 -nodes \
  -keyout certs/server.key -out certs/server.crt \
  -subj '/CN=localhost' \
  -addext 'subjectAltName=DNS:localhost,IP:127.0.0.1'
chmod 600 certs/server.key
```

```bash
docker compose up -d postgres
export DATABASE_URI='postgres://gophkeeper:gophkeeper@localhost:5432/gophkeeper?sslmode=disable'
export AUTH_SECRET='replace-this-with-a-random-32-byte-secret'
export TLS_CERT='./certs/server.crt'
export TLS_KEY='./certs/server.key'
go run ./cmd/gophkeeper-server
```

Клиенту нужно передать сертификат, которому он доверяет. Мастер-пароль запрашивается в терминале без отображения введённых символов:

```bash
export GOPHKEEPER_CA='./certs/server.crt'
export GOPHKEEPER_SERVER_NAME='localhost'
go run ./cmd/gophkeeper register alice
go run ./cmd/gophkeeper add credentials \
  --name 'Рабочая почта' --metadata 'example.com' \
  --login 'alice@example.com' --secret 'mail-password'
go run ./cmd/gophkeeper list
```

После успешной синхронизации команды `list`, `get` и `search` используют последний зашифрованный снимок, если сервер временно недоступен.

## Команды клиента

```text
register LOGIN                         регистрация и создание локальной сессии
login LOGIN                            аутентификация и обновление сессии
add credentials|text|binary|card      добавление записи
update TYPE ID VERSION                 изменение известной версии записи
list                                   список актуальных записей
get ID                                 просмотр записи
search QUERY                           поиск по названию и метаинформации
delete ID VERSION                      удаление известной версии записи
sync --since CURSOR                    получение изменений после курсора
version                                версия, дата и коммит сборки
```

Для бинарной записи используются `add binary --file PATH` и `get ID --output PATH`. Полный список параметров доступен через `gophkeeper COMMAND --help`.

## Конфигурация сервера

| Флаг | Переменная окружения | Назначение |
|---|---|---|
| `-a` | `RUN_ADDRESS` | адрес gRPC-сервера, по умолчанию `127.0.0.1:3200` |
| `-d` | `DATABASE_URI` | строка подключения к PostgreSQL |
| `-auth-secret` | `AUTH_SECRET` | секрет подписи токенов |
| `-tls-cert` | `TLS_CERT` | сертификат TLS |
| `-tls-key` | `TLS_KEY` | приватный ключ TLS |
| `-token-ttl` | `TOKEN_TTL` | срок действия токена, по умолчанию `24h` |

Сертификат и приватный ключ обязательны: сервер не поддерживает незашифрованные соединения.

## Конфигурация клиента

| Флаг | Переменная окружения | Назначение |
|---|---|---|
| `-a`, `--address` | `GOPHKEEPER_ADDRESS` | адрес сервера |
| `--ca` | `GOPHKEEPER_CA` | доверенный сертификат сервера |
| `--server-name` | `GOPHKEEPER_SERVER_NAME` | имя сервера в сертификате |
| `--timeout` | `GOPHKEEPER_TIMEOUT` | таймаут запроса |
| `--session` | `GOPHKEEPER_SESSION` | путь к файлу сессии |
| `--cache` | `GOPHKEEPER_CACHE` | путь к зашифрованному локальному кешу |

Файл сессии хранит только токен, логин и соль. Локальный кеш целиком шифруется AES-256-GCM. Мастер-пароль и ключ шифрования на диск не записываются и не принимаются через аргументы командной строки или переменные окружения.

## Сборка

```bash
make build
make build-all
```

Версия клиента задаётся на этапе сборки:

```bash
go build -ldflags "\
  -X main.buildVersion=v1.0.0 \
  -X main.buildDate=$(date -u +%Y-%m-%dT%H:%M:%SZ) \
  -X main.buildCommit=$(git rev-parse --short HEAD)" \
  -o bin/gophkeeper ./cmd/gophkeeper
```

## Тестирование

```bash
make test
make cover
```

Проверка миграции метаданных на отдельной тестовой PostgreSQL-базе:

```bash
TEST_DATABASE_URI='postgres://user:password@localhost:5432/testdb?sslmode=disable' \
  go test -tags=integration ./internal/storage -run TestPostgresMetadataMigration
```

Тест создаёт временную схему и удаляет её после завершения.

Юнит-тесты и тесты полного gRPC-сценария покрывают регистрацию, авторизацию, шифрование, синхронизацию, конфликты версий, удаление, конфигурацию и CLI. Покрытие превышает требуемые 70%.
