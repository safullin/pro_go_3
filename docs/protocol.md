# Протокол GophKeeper

Клиент и сервер взаимодействуют по gRPC. Контракт находится в `proto/gophkeeper.proto`.

## Авторизация

Методы `Register` и `Login` возвращают подписанный сервером токен и индивидуальную соль пользователя. Для остальных методов клиент передаёт метаданные:

```text
authorization: Bearer <token>
```

Токен содержит идентификатор пользователя, логин и срок действия. Подпись вычисляется HMAC-SHA256. Пароль пользователя хранится только в виде bcrypt-хеша.

## Шифрование

Ключ длиной 256 бит выводится из мастер-пароля и соли с помощью Argon2id. Перед отправкой полезная нагрузка сериализуется в JSON и шифруется AES-256-GCM. Идентификатор и тип записи входят в authenticated additional data, поэтому зашифрованный блок нельзя незаметно перенести в другую запись.

## Синхронизация

Каждое создание, изменение или удаление получает новую монотонную версию. `ListSecrets` принимает последнюю известную версию и возвращает только более новые изменения вместе со следующим курсором. Удаление хранится в виде tombstone, поэтому его получают остальные клиенты.

При изменении и удалении клиент передаёт ожидаемую версию. Если запись уже была изменена, сервер возвращает gRPC-код `Aborted`; клиент должен синхронизироваться и повторить действие осознанно.
